## sakura‑orm とは？

`sakura-orm` は、Python だけでシンプルにデータベース操作ができる軽量 ORM（Object‑Relational Mapping）です。  
- **軽量**：依存は `pymysql`、`psycopg2`、`sqlite3` などの DB ドライバだけ  
- **宣言的にモデル定義**：Django のようにクラスでテーブル構造を記述  
- **SQL を意識しなくても CRUD が書ける**  
- **トランザクション・マイグレーション機能も備える**  

以下では、**インストール → 接続設定 → モデル定義 → 基本的な CRUD** の流れをコード例とともに解説します。

## 2️⃣ データベース接続設定

`sakura-orm` は **グローバルな `Database` オブジェクト** を作成し、そこに接続情報を渡します。

```python
# db_config.py
from sakura_orm import Database

# 例: SQLite
db = Database(
    driver="sqlite",
    database="example.db"   # ファイル名
)

# 例: MySQL
# db = Database(
#     driver="mysql",
#     host="127.0.0.1",
#     port=3306,
#     user="root",
#     password="secret",
#     database="myapp"
# )
```

> **ポイント**  
> - `Database` はシングルトン的に扱われ、`db` をインポートすればどこからでも同じ接続が利用できます。  
> - 接続は **遅延初期化** され、最初にクエリが走ったときに実際に DB に接続します。

## 3️⃣ モデル（テーブル）定義

`sakura-orm` のモデルは `sakura_orm.Model` を継承し、フィールドは `sakura_orm.fields` からインポートします。

```python
# models.py
from sakura_orm import Model
from sakura_orm.fields import (
    IntegerField,
    CharField,
    TextField,
    DateTimeField,
    ForeignKey,
)

class User(Model):
    """ユーザ情報テーブル"""
    id = IntegerField(primary_key=True)          # PK
    username = CharField(max_length=50, unique=True)
    email = CharField(max_length=255, unique=True)
    created_at = DateTimeField(auto_now_add=True)

class Post(Model):
    """ブログ記事テーブル"""
    id = IntegerField(primary_key=True)
    title = CharField(max_length=200)
    body = TextField()
    author = ForeignKey(User, related_name="posts")   # 1対多リレーション
    created_at = DateTimeField(auto_now_add=True)
    updated_at = DateTimeField(auto_now=True)
```

### フィールドの主な種類

| フィールド | 主な引数 | 説明 |
|-----------|----------|------|
| `IntegerField` | `primary_key`, `default`, `null` | 整数 |
| `CharField` | `max_length`, `unique`, `null`, `default` | 文字列（VARCHAR） |
| `TextField` | `null`, `default` | 長文（TEXT） |
| `DateTimeField` | `auto_now`, `auto_now_add`, `null` | 日付時刻 |
| `FloatField` | `null`, `default` | 浮動小数点 |
| `BooleanField` | `default` | 真偽値 |
| `ForeignKey` | `to`, `related_name`, `null` | 他テーブルへの外部キー |
| `JSONField` | `default` | JSON 文字列（PostgreSQL の JSONB もサポート） |

## 4️⃣ テーブル作成（マイグレーション）

`sakura-orm` には **自動マイグレーション** 機能があり、モデル定義だけでテーブルを作成できます。

```python
# migrate.py
from db_config import db
from models import User, Post

def migrate():
    # まだテーブルが無ければ作成、既にあればスキーマ差分を検出して ALTER を実行
    db.create_all([User, Post])

if __name__ == "__main__":
    migrate()
```

> **注意**  
> - `create_all()` は **モデルのフィールド情報** から `CREATE TABLE` 文を生成します。  
> - 変更があった場合は `ALTER TABLE` を自動で実行しますが、複雑なスキーマ変更（例：カラム名変更）は手動マイグレーションが必要です。  
> - 本番環境では、`alembic` のような外部マイグレーションツールと併用することも可能です（`sakura-orm` の `Migration` クラスをラップして利用）。

## 5️⃣ 基本的な CRUD 操作

### 5‑1️⃣ INSERT（レコード作成）

```python
# create_user.py
from db_config import db
from models import User, Post

# 1️⃣ ユーザ作成
alice = User(
    username="alice",
    email="alice@example.com"
)
alice.save()          # INSERT が実行され、PK が自動設定される

# 2️⃣ 記事作成（ForeignKey でリレーション）
post = Post(
    title="はじめてのsakura-orm",
    body="sakura-orm の使い方をまとめました。",
    author=alice          # ← User インスタンスをそのまま渡す
)
post.save()
```

### 5‑2️⃣ SELECT（データ取得）

```python
# query_examples.py
from models import User, Post

# 1️⃣ 全件取得
all_users = User.objects.all()
for u in all_users:
    print(u.id, u.username, u.email)

# 2️⃣ 条件検索（filter）
active_alice = User.objects.filter(username="alice").first()
print(active_alice.email)

# 3️⃣ 1対多リレーションの取得（逆参照）
alice_posts = active_alice.posts  # related_name="posts" が自動でクエリを生成
for p in alice_posts:
    print(p.title, p.created_at)

# 4️⃣ 複数条件・OR/AND
recent_posts = Post.objects.filter(
    created_at__gte="2024-01-01",   # __gte は >=
    title__icontains="sakura"      # 部分一致（大文字小文字無視）
).order_by("-created_at")          # 降順

for p in recent_posts[:5]:          # スライスで LIMIT を付与
    print(p.title, p.author.username)
```

#### フィルタ構文のポイント

| 演算子 | 例 | 説明 |
|------|------|------|
| `field__exact` | `username__exact="bob"` | 完全一致 |
| `field__icontains` | `title__icontains="Python"` | 大文字小文字を無視した部分一致 |
| `field__gt` / `field__lt` | `age__gt=30` | > / < |
| `field__in` | `id__in=[1,2,3]` | IN 演算 |
| `field__isnull` | `email__isnull=True` | NULL 判定 |
| `field__startswith` / `endswith` | `username__startswith="a"` | 前方/後方一致 |

### 5‑3️⃣ UPDATE（更新）

```python
# update_user.py
from models import User

alice = User.objects.filter(username="alice").first()
alice.email = "alice_new@example.com"
alice.save()          # UPDATE が走ります
```

> **Tip**  
> `save()` は **差分検知** を行い、変更があったフィールドだけ `UPDATE` します。  
> 変更が無い場合は何も実行されません。

### 5‑4️⃣ DELETE（削除）

```python
# delete_post.py
from models import Post

# 条件に合うレコードを一括削除
Post.objects.filter(title__icontains="テスト").delete()

# 1 件だけ削除したいときはインスタンスから
post = Post.objects.filter(id=5).first()
post.delete()
```

## 6️⃣ トランザクション制御

`sakura-orm` は **コンテキストマネージャ** でトランザクションを扱えます。

```python
# transaction_example.py
from db_config import db
from models import User, Post

def create_user_and_posts():
    with db.transaction():          # ← ここで BEGIN が走る
        alice = User(username="alice", email="alice@example.com")
        alice.save()                # INSERT

        # 複数の INSERT が同一トランザクション内で実行
        for i in range(3):
            Post(
                title=f"テスト記事 {i+1}",
                body="本文です。",
                author=alice
            ).save()

        # 何か例外が起きたら自動で ROLLBACK
        # raise ValueError("テスト例外")

    # 正常に抜けたら COMMIT が自動で走ります
```

## 7️⃣ 高度なクエリ（Raw SQL・アノテーション）

### 7‑1️⃣ Raw SQL の実行

```python
# raw_sql.py
from db_config import db

# SELECT の結果を dict のリストで取得
rows = db.execute(
    "SELECT id, username, email FROM user WHERE email LIKE %s",
    params=("%@example.com",)
)

for row in rows:
    print(row["username"], row["email"])
```

### 7‑2️⃣ アノテーション（集計・サブクエリ）

`sakura-orm` の `annotate()` は Django の `annotate` と同様に、集計関数を付加できます。

```python
# aggregation_example.py
from models import User, Post
from sakura_orm import functions as F

# 各ユーザが書いた記事数を取得
users_with_counts = User.objects.annotate(
    post_count=F.Count("posts")   # related_name="posts"
).order_by("-post_count")

for u in users_with_counts:
    print(u.username, u.post_count)
```

## 8️⃣ マイグレーションのベストプラクティス

| 作業 | コマンド例 | 説明 |
|------|--------------------------|------|
| 初期テーブル作成 | `python migrate.py` | `create_all()` が全モデルのテーブルを作成 |
| カラム追加 | `python migrate.py --add-field User.age IntegerField` | `Migration` クラスで `add_column` を呼び出す |
| カラム削除 | `python migrate.py --remove-field User.age` | 同様に `drop_column` |
| テーブル名変更 | 手動で `ALTER TABLE` を書くか、`Migration.rename_table(old, new)` を利用 | 変更は手動が安全です |

`sakura-orm` には簡易的な `Migration` ヘルパーがあり、以下のように使います。

```python
# migration_helper.py
from db_config import db
from sakura_orm.migration import Migration

def add_user_age():
    mig = Migration(db)
    mig.add_column(
        table="user",
        column="age",
        column_type="INTEGER",
        default=0,
        nullable=False
    )
    mig.apply()   # 実際に ALTER が走ります
```

## 9️⃣ 完全なサンプルアプリ（SQLite + FastAPI での利用例）

以下は **FastAPI** と組み合わせた実装例です。  
（FastAPI は非同期フレームワークですが、`sakura-orm` は同期 API のため、リクエストハンドラは `def` にして `await` しません）

```python
# main.py
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from db_config import db
from models import User, Post

# アプリ起動時にテーブル作成
@app.on_event("startup")
def on_startup():
    from models import User, Post
    db.create_all([User, Post])

app = FastAPI()

# ---------- Pydantic スキーマ ----------
class UserCreate(BaseModel):
    username: str
    email: str

class PostCreate(BaseModel):
    title: str
    body: str
    author_id: int

# ---------- エンドポイント ----------
@app.post("/users/")
def create_user(payload: UserCreate):
    user = User(username=payload.username, email=payload.email)
    user.save()
    return {"id": user.id, "username": user.username}

@app.get("/users/{user_id}")
def get_user(user_id: int):
    user = User.objects.filter(id=user_id).first()
    if not user:
        raise HTTPException(status_code=404, detail="User not found")
    return {"id": user.id, "username": user.username, "email": user.email}

@app.post("/posts/")
def create_post(payload: PostCreate):
    author = User.objects.filter(id=payload.author_id).first()
    if not author:
        raise HTTPException(status_code=404, detail="Author not found")
    post = Post(title=payload.title, body=payload.body, author=author)
    post.save()
    return {"id": post.id, "title": post.title}

@app.get("/posts/")
def list_posts(limit: int = 10, offset: int = 0):
    posts = Post.objects.order_by("-created_at")[offset: offset + limit]
    return [
        {
            "id": p.id,
            "title": p.title,
            "author": p.author.username,
            "created_at": p.created_at.isoformat(),
        }
        for p in posts
    ]
```

> **ポイント**  
> - `db.create_all([...])` を `startup` イベントで呼び出すことで、サーバ起動時に自動でテーブルが作られます。  
> - `User.objects.filter(...).first()` のように **チェーン可能** な QuerySet が提供されます。  
> - FastAPI の `BaseModel` と組み合わせると、リクエストバリデーションが自動で行われます。

## 10️⃣ まとめ

| 項目 | 内容 |
|------|------|
| **インストール** | `pip install sakura-orm` |
| **接続設定** | `Database(driver=..., ...)` を作成し、モジュールで共有 |
| **モデル定義** | `class Xxx(Model):` + `fields` |
| **テーブル作成** | `db.create_all([Model1, Model2])` |
| **CRUD** | `instance.save()`, `Model.objects.filter(...).first()`, `instance.delete()` |
| **トランザクション** | `with db.transaction():` |
| **集計・アノテーション** | `annotate()`, `functions.Count` など |
| **マイグレーション** | `db.create_all()` + `Migration` ヘルパー |
| **実務での利用例** | FastAPI/Django 風ハンドラ、CLI スクリプト、バッチ処理 |

`sakura-orm` は **「シンプルさ」** と **「Pythonic に書ける」** を両立させた ORM です。  
上記のコードをベースに、実際のプロジェクトで **モデル設計 → マイグレーション → ビジネスロジック** の流れを構築すれば、SQL の細かい記述に悩むことなくデータベース操作が可能になります。
