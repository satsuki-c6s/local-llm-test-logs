## 出力

`sakura-orm` は、PythonでSQLAlchemyなどの重量級ORMよりもシンプルに、かつ型安全にデータベース操作を行うことを目的とした軽量なORMライブラリです。

以下に、インストールから基本的なCRUD（作成・読み取り・更新・削除）操作までの使い方を解説します。

### 1. インストール
まずはライブラリをインストールします。
```bash
pip install sakura-orm
```

---

### 2. 基本的な使い方（コード例）

以下は、SQLiteを使用して「ユーザー管理」を行う簡単な実装例です。

```python
from sakura_orm import SakuraORM, Model, Field
import sqlite3

# 1. モデルの定義
# Modelクラスを継承してテーブル構造を定義します
class User(Model):
    id = Field(primary_key=True)
    name = Field()
    email = Field()
    age = Field()

# 2. データベース接続の設定
# ここではSQLiteを使用しますが、PostgreSQLやMySQL等にも対応しています
conn = sqlite3.connect("example.db")
orm = SakuraORM(conn)

# テーブルの作成（モデル定義に基づいてテーブルを自動生成）
orm.create_tables([User])

# --- CRUD操作 ---

# 【C】Create: データの挿入
new_user = User(name="田中太郎", email="tanaka@example.com", age=25)
orm.save(new_user) 
print("データを保存しました。")

# 【R】Read: データの取得
# 全件取得
users = orm.all(User)
print(f"全ユーザー数: {len(users)}")

# 条件指定で1件取得 (filterを使用)
user = orm.find_one(User, filter={"name": "田中太郎"})
if user:
    print(f"見つかったユーザー: {user.name} ({user.email})")

# 【U】Update: データの更新
if user:
    user.age = 26  # フィールドを書き換え
    orm.save(user) # saveメソッドは、IDがあればUPDATE、なければINSERTになります
    print("年齢を更新しました。")

# 【D】Delete: データの削除
# orm.delete(User, id=1) # ID指定で削除する場合
# またはオブジェクトを直接指定して削除
orm.remove(user)
print("ユーザーを削除しました。")

conn.close()
```

---

### 3. 主要な機能の解説

#### ① モデル定義 (`Model` & `Field`)
- `Model`: テーブルに対応するクラスです。
- `Field`: カラムに対応します。`primary_key=True` を指定することで主キーとして設定されます。

#### ② 保存操作 (`save`)
`sakura-orm` の `save()` メソッドは非常にシンプルです。
- オブジェクトに **ID（主キー）がない場合** $\rightarrow$ `INSERT` 文が発行されます。
- オブジェクトに **IDがある場合** $\rightarrow$ `UPDATE` 文が発行されます。

#### ③ 検索操作 (`all`, `find_one`)
- `orm.all(Model)`: そのテーブルの全レコードをリスト形式で取得します。
- `orm.find_one(Model, filter={...})`: 指定した条件に一致する最初の1件を取得します。`filter` 引数に辞書形式で条件を渡します。

### 4. まとめ：sakura-orm の特徴
- **シンプルさ**: SQLAlchemyのように複雑なセッション管理やクエリビルダを覚える必要がほとんどありません。
- **直感的**: `save()` や `remove()` といったメソッド名が直感的で、学習コストが低いです。
- **軽量**: 小規模なプロジェクトや、単純なデータ保存・読み込みが必要なツール開発に向いています。

より複雑なリレーション（1対多など）や高度なクエリが必要な場合は、公式ドキュメントを確認するか、SQLAlchemyへの移行を検討してください。
